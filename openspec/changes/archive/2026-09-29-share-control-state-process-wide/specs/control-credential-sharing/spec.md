## Purpose

让远程控制的一次性令牌在其对应的待处理请求仍然有效期间**跨 location 存活**（不因宿主加载新目录、插件热重载或配置变更而静默失效），同时在多 server 进程与多机器之间保持严格隔离。

## ADDED Requirements

### Requirement: 令牌在同一 server 进程内跨 location 有效

系统 SHALL 使已发出的待处理令牌在**同一 server 进程内的任何 location** 都能被受理，不因插件在该进程内新增实例（例如宿主加载了另一个目录）而失效。

受理 MUST 包含对宿主应答的**真实执行**（而非仅通过校验）。

#### Scenario: 打开新项目目录后已发出的令牌仍可用
- **WHEN** 已就某会话发出授权/提问通知并附带令牌，随后宿主加载了另一个 location 使活动实例发生变更
- **THEN** 用户仍可通过该令牌完成应答，且收到成功回执

#### Scenario: 令牌在等待应答期间不被作废
- **WHEN** 通知已发出、用户尚未应答，此期间活动实例发生变更
- **THEN** 该令牌对应的待处理条目**未被丢失**，用户应答后投递到宿主

### Requirement: 插件重载后令牌仍然有效

系统 SHALL 使插件在同一进程内被重新加载（模块重新求值）后，之前发出的令牌继续有效。

#### Scenario: 热重载不失效
- **WHEN** 插件因文件变更被重载，此前存在待处理令牌
- **THEN** 重载后该令牌仍可被受理并成功应答

### Requirement: 跨 server 进程与跨机器保持隔离

系统 SHALL 将上述共享限制在**单个 server 进程**内：不同进程（含同机并存的多个 server 进程）与不同机器之间，各自的令牌互不被受理，且互不产生回执。

#### Scenario: 同机两个 server 进程互不受理
- **WHEN** 同机并存两个 server 进程，其中一个进程发出令牌，其命令被另一个进程读到
- **THEN** 另一个进程 MUST NOT 受理该令牌，MUST NOT 发出回执（由持有者受理）

#### Scenario: 不同机器互不受理
- **WHEN** 两台机器共用同一通知话题，甲机的令牌被乙机读到
- **THEN** 乙机 MUST NOT 受理，MUST NOT 发出回执

### Requirement: 配置变更后新参数生效且不丢已发出令牌

当注册表相关配置（令牌有效期、容量上限）发生变化时，系统 SHALL 按新参数重建注册表，**同时保留**此前已发出的待处理条目；容量上限变小时 MUST 使存量条目被裁剪到新上限。

#### Scenario: 有效期变更后新值生效且条目保留
- **WHEN** 令牌有效期配置变更，此前存在待处理令牌
- **THEN** 重建后的注册表使用新的有效期判定
- **AND** 此前发出且仍在有效期内的令牌仍可被受理

#### Scenario: 容量上限变小时立即裁剪
- **WHEN** 容量上限配置调小，存量条目多于新上限
- **THEN** 存量条目被裁剪到新上限（保留最新者）

#### Scenario: 配置未变时不重建
- **WHEN** 插件重载但注册表相关配置未变化
- **THEN** 复用既有注册表（令牌与条目不受影响）

### Requirement: 静默策略不变

系统 MUST NOT 因本次变更引入新的回执噪音：无归属令牌、已消费/已过期令牌仍一律静默，仅记日志。

#### Scenario: 异主令牌仍静默
- **WHEN** 收到的令牌不属于本 server 进程
- **THEN** 不执行、不回执，仅记录日志
